# 数据定义

票号与原始编号均为字符串，保留前导零。称重支持 kg、公斤与 t，统一为 kg，单价为 CNY/kg。
毛重与皮重按票号和版本配对，品类、单价、扣杂率与更正目标必须一致。计价重量=(毛重−皮重)×(1−扣杂率)，先量化到0.001kg，再乘单价，金额四舍五入到0.01CNY。
每票第一版不填写 replaces。后续版本只能替代当前生效版，分支或缺基版整票阻断结算。已支付额为各版本中最大累计已付值，待付=最终应付−累计已付；负待付表示待收回。
同编号同原值仅计一次；同编号不同原值全部隔离。空文件、全空行和仅表头分别报错。原始输入计数包括空行及重复表头，对账会分别解释。

## 月度代扣经营税

按月为船户累计代扣。`T(x)` 是「当月累计计税依据 x」下的应扣税额：先扣免税额度，再按累进档计算，结果四舍五入到 0.01CNY。免税额度随当月全部票累计消耗，不在票间重复给。

票号归属船户由 `context.ticket_owners` 指定，船户纳税人身份取自 `context.taxpayers`（`tax_id` 至少 8 位、`status` 为有效）。户级累计计税依据=该户当月生效版本成交额之和，与应付对账的生效票一致。

结算序：先全部基版（票号升序），再月末更正批（票号、版本升序）。每一笔登记

    本次应扣/应退 = T(登记后累计计税依据) − T(登记前累计计税依据)

因此已申报税单不被整月重算改写；月末更正的跨档影响只由一条增量流水承接；后续票从更新后的位置继续计算。逐笔增量之和恰好等于 `T(月末累计计税依据)`。

任一船户出现以下情况时该户当月整体**暂缓**，不申报、不扣税、不退款：缺少有效纳税人身份（`MISSING_TAXPAYER`/`INVALID_TAXPAYER`/`OWNER_UNASSIGNED`）；更正链未闭合（`CHAIN_OPEN`）；户级累计与票级结果不符或账本核对不符（`OWNER_TICKET_MISMATCH`/`ENTRY_PAYLOAD_CONFLICT`）。被暂缓的票仍以 `blocked` 流水留证。

申报账本以 `entry_id`（船户/月份/票/版本/前后金额/规则版本哈希）幂等登记：同一更正重跑只命中复用，不重复扣税或退款；申报失败整批回滚并记失败日志，既有税单原样保留。本次可支付净额=结算待付−本月应扣税。

归档封存保存逐版证据、隔离原因、代扣税结论和运行摘要，非支付执行系统。数据使用虚构编号，不连接实际支付渠道。
